# 原版怪物：獵殺姿態、攻擊前搖、抽搐與 CC0 叫聲

日期：2026-11-20　分支：`feat/brutal-creatures`

## 目的

上一版的怪物動作只在原版姿勢上疊加小角度（多為 0.05～0.2 弧度），怪物進入攻擊狀態時手臂只多抬 0.07 弧度；叫聲則全部是程式合成。看起來「有重量」，但不夠野蠻，也不夠恐怖。

這次要讓原版怪物在看與聽兩方面都更野蠻：

1. **獵殺姿態**：鎖定目標後換一套壓低、前傾、帶威嚇的姿勢。
2. **攻擊前搖（真前搖）**：出手前先蓄力，伺服器真的延後那一擊，出手時往前撲。玩家看得出下一擊何時落下，可以翻滾或退開。
3. **抽搐**：不死系、終界使者與嘎枝會不規則地猛然轉頭、抽肩、踉蹌。
4. **叫聲**：有喉嚨的怪物，叫聲改用 CC0 錄音為底重新合成；另新增出手前的「前搖嘶吼」作為預警。

## 目標

- 每個近戰原版怪物出手前都有可讀的前搖，動畫、聲音和傷害判定在同一個 tick 對齊。
- 前搖的解法是**翻滾**，或轉身衝刺拉開距離；只是直線後退會被撲擊追上。
- 鎖定目標的怪物和閒晃的怪物，從姿勢就能分辨。
- 叫聲聽起來像真的喉嚨與胸腔，而不是電子音；同一族群有一致的聲音性格。

## 非目標

- 不做嗅血追獵、衝刺撲擊、呼喚同伴、怪物斷肢、玩家爬行、掙脫處決（之後各自評估）。
- 不改遠程攻擊（弓、弩、火球、藥水、喚魔者尖牙）與其時機。
- 不改中立生物的聲音（羊駝、熊貓、山羊、海豚、蜜蜂、鐵魔像）。狼與北極熊可能是寵物或幼獸，只重做目前已經取代的戰鬥聲（狼的 `growl`、北極熊的 `warning`），待機、受傷、死亡、嗚咽等維持原版。
- 不改非叫聲的音效（腳步、射擊、游泳、開關殼、門、硫磺立方的互動聲等）。
- 不新增怪物、不改怪物的數值（血量、傷害、速度）。

## 不能接受的結果（即使技術上可行）

- 前搖讓怪物變得好欺負：只要往後退一步就永遠打不到人。
- 動畫和傷害對不上（看到揮空卻扣血，或還在蓄力就扣血）。
- 叫聲聽起來滑稽或卡通（部分 CC0 來源是用嘴巴模仿的，處理不足會很可笑）。
- 音量忽大忽小、蓋過戰鬥資訊。

## 限制

- Minecraft 26.3、Fabric；伺服器權威：前搖的開始、出手與命中只在伺服器決定，客戶端只負責呈現。
- 不改存檔格式：前搖狀態只存在記憶體並同步給客戶端，不寫入存檔。
- Mixin 只在找不到事件時使用，注入點盡量小。
- 玩家看得到的文字（字幕）需有 `zh_tw.json` 與 `en_us.json`。
- 美術與音效規則（`CONTRIBUTING.md`）：音效可用已查證的 CC0 錄音製作，倉庫只提交成品（OGG、JSON），來源逐項記在 `CREDITS.md`；原始錄音與產生腳本不進倉庫。
- 與處決相容：前搖延後的那一擊落下時，若玩家雙腿壞死，照現有規則轉成處決起手（`ExecutionService.begins`）。

## 做法比較

| 做法 | 內容 | 取捨 |
| --- | --- | --- |
| **A. 真前搖（採用）** | 伺服器攔下出手，開始前搖並同步給客戶端，前搖結束時才真正造成傷害，出手時往前撲。 | 動畫、聲音、判定完全對齊，翻滾有意義；近戰節奏稍慢，用撲擊距離補回。 |
| B. 純動畫 | 不改傷害時機，只在攻擊冷卻快結束時播蓄力動畫。 | 改動小；但怪物剛走到身邊的第一擊仍是瞬間打出，前搖常來不及播，看起來對不上。 |

使用者選擇 A。

## 設計

### 1. 攻擊前搖（伺服器）

**攔截點**：原版不論是近戰 AI 目標（`MeleeAttackGoal`）或 brain 型行為（`MeleeAttack`），判定可以出手時都會呼叫 `Mob.doHurtTarget(ServerLevel, Entity)`。在這裡攔截，一次涵蓋兩種 AI。

**適用條件**：攻擊者有 `EnemyRig` 且該族群有前搖長度（見下表），目標是適用身體系統的玩家（`BodyService.applies`，即生存／冒險模式）。怪物打其他生物時維持原版。

**流程**：

1. `doHurtTarget` 被呼叫，且怪物目前沒有前搖 → 不造成傷害（回傳 false），開始前搖：記錄開始時間、長度、目標，同步給所有客戶端；在怪物位置播放該怪物的前搖嘶吼。
2. 前搖期間：怪物停止導航，持續轉向目標，並以自身移動速度的 30% 朝目標慢慢逼近（壓迫感，也避免玩家退一步就脫離）。AI 目標照常運作，所以攻擊冷卻照常倒數（各族群前搖長度都小於原版攻擊間隔 20 tick，節奏不會被拉長）。前搖期間再次呼叫 `doHurtTarget` 一律忽略。
3. 前搖結束（出手）：怪物朝目標**當下的位置**往前撲（給一次水平速度），並揮手（讓原版揮擊動畫對齊出手）。命中範圍 = 怪物的近戰攻擊範圍，沿撲擊方向延伸「撲擊距離 + 追擊距離」；追擊距離 = 目標從前搖開始到現在拉開的距離，上限 1.0 格。目標仍在範圍內、看得到、且在同一個世界時，才呼叫原本的 `doHurtTarget` 造成傷害。翻滾無敵與盾牌等照原版判定。
   - 預期手感：直線後退（約 0.22 格/tick）會被追上；轉身衝刺（約 0.28 格/tick）在前搖較長的怪物面前逃得掉；翻滾抓對時機一定躲得掉；雙腿壞死的玩家逃不掉。
   - 實測若手感不對，實作者可調整：前搖長度 ±2 tick、逼近速度 20～40%、追擊上限 0.8～1.4 格。調整後的數值要寫回本文件的表格。
4. 出手後保留 5 tick 的收招狀態給客戶端播放，然後清除。

**中止條件**：怪物死亡或被移除、怪物開始處決、怪物變成乘客、劫毀獸暈眩、目標死亡／換世界／變成創造或旁觀模式。**受到傷害不會中止前搖**（怪物硬吃攻擊才夠野蠻；被擊退出範圍時自然會揮空）。

### 2. 獵殺姿態（客戶端）

條件：怪物處於攻擊狀態（`Mob.isAggressive()`，已同步給客戶端）且沒有在前搖。姿勢在 8 tick 內淡入、淡出。brain 型怪物（豬布林、蠻兵、疣豬獸、殭屍疣豬獸、伏守者、嘎枝）若不會設定攻擊狀態，由伺服器在牠有攻擊目標時另外同步一個標記（實作時逐一確認）。

| 族群 | 姿勢 |
| --- | --- |
| 殭屍類、屍殼、溺屍、殭屍化豬布林 | 上身前傾約 0.3 弧度、頭往前探且略低、聳肩、雙臂往前伸並略為張開；步伐變短、左右晃動加大 |
| 骷髏類 | 駝背、歪頭、手臂鬆垂，身體細碎抖動 |
| 豬布林、蠻兵、衛道士 | 半蹲、持武器的手舉起 |
| 終界使者 | 雙臂張開、身體前傾 |
| 伏守者、嘎枝 | 同殭屍類但更沉重、晃動更慢 |
| 蜘蛛類 | 前兩對腳抬起示威、腹部壓低 |
| 疣豬獸、劫毀獸、狼、北極熊 | 頭壓低、肩膀拱起，像在潛行逼近 |

### 3. 前搖與出手的動畫（客戶端）

用前搖附件算出進度（0～1 為蓄力，之後 5 tick 為出手與收招），並以客戶端的世界時間加上 partial tick 平滑播放。

- **人形**：蓄力時重心移到後腳、上身後仰、雙臂往後上方拉起、頭往後收，越接近出手抖得越厲害；出手時上身猛然前傾、雙臂劈下或前刺，整體往前撲，再落回站姿。
- **蜘蛛類**：前四隻腳高舉、身體後坐，出手時整隻往前撲咬。
- **四足（狼、熊、疣豬獸、劫毀獸）**：後腿下蹲、頭壓低，出手時頭往前上方頂。
- **蠹魚、終界蟎**：身體捲起，出手時快速彈出。
- 前搖期間覆蓋原版在前搖開始時就播的揮手動畫；出手時伺服器重新揮手，讓原版揮擊與出手對齊。

### 4. 抽搐（客戶端）

對象：原版 `minecraft:undead` 標籤內、且有人形或四足骨架的怪物，以及終界使者、嘎枝。

- 隨機但可重現：以實體 id 與時間區段決定，所有玩家看到的抽搐一致。
- 平常每 2～6 秒一次，獵殺狀態時每 1～2 秒一次；前搖與處決期間不抽搐。
- 動作種類：猛然轉頭或歪頭（0.35～0.6 弧度，2 tick 到位、停 1～3 tick、4 tick 回正）、單肩抽動、單腳一軟的踉蹌。
- 骷髏抽搐時骨頭喀啦作響（沿用現有骨頭聲，不需新素材）。

### 6. 處決改成雙人招式（2026-11-20 使用者確認）

**現在的問題**：怪物和玩家的實際距離每次不同（實測 0.6～1.4 格），但處決動畫的位移是寫死的，距離近時怪物身體會插進玩家身體；五種處決都只是「蓄力、撞一下」，玩家這邊也只有一套通用倒地動畫。

**做法**：每招由兩條同步的關鍵影格動畫組成（怪物一條、玩家一條），用現有的 `Clip` 系統，放在 `assets/mistinn/anim/execution/<招式>/striker.json` 與 `victim.json`，總長度與各個「接觸點」寫在動畫的頂層欄位。伺服器只依招式的長度與接觸點計時，動作細節全在動畫檔。

**站位與穿模**：處決開始時，伺服器在 3 tick 內把怪物滑到這招固定的站位（玩家正前方、招式指定的距離），之後鎖住雙方：怪物 AI 暫停（沿用現有做法），玩家的移動速度與跳躍歸零（屬性修正，處決結束時移除）。跳躍、衝刺、甩飛等大動作只做畫面上的位移，不移動實體，所以兩個模型每次的相對位置都一樣。站位被方塊擋住時，改用最近的空位；完全沒有空位就不發動處決，這一擊照一般攻擊處理。

**招式**（長度 2.5～4 秒，都是多段動作）：

| 招式 | 怪物 | 動作 | 中途受的傷 |
| --- | --- | --- | --- |

**規則**：
- 處決由前搖結束後落下的那一擊觸發，抓住的接觸發生在處決一開始；單人自救只能靠在前搖期間翻滾。
- 被抓住後，只有**其他玩家**打中怪物才能打斷（受害者自己的攻擊不算）；打斷期限到致命一擊之前。
- 每個接觸點照上表造成骨折或出血（透過 `WoundService`），被救下來時會留著這些傷。致命一擊仍是對軀幹的處決傷害。
- 處決鏡頭依招式調整取景，確保兩個角色都在畫面內。

### 7. 骷髏類的處決（2026-11-20 使用者指定）

- **骷髏、流髑（雪地）、沼骸、枯骸（沙漠）**：用弓箭爆頭。拿弓的骷髏射出的箭命中雙腿壞死的玩家時，這一箭被處決接管（不造成傷害、箭消失），開始「爆頭」：骷髏停下、轉向玩家，重新搭箭、慢慢拉滿並瞄準頭部（約 1.5 秒），放箭；箭在畫面上飛向玩家頭部，命中即死。距離不限於近戰，只要在原版弓的射程內且看得到玩家；放箭前失去視線或被其他玩家打中就中止。玩家這邊跪地掙扎、抬頭看著骷髏，中箭時頭向後一甩倒下，死亡過場中箭會插在頭上。
- **凋零骷髏**：近戰砍殺（上一節的「斬殺」）。沒拿弓、近戰出手的一般骷髏類也用斬殺。

### 8. 死亡畫面（2026-11-20 使用者指定）

## 驗證

- 客戶端遊戲測試（處決測試同一個世界或新的獨立世界）：
  - 屍殼對雙腿完好的玩家出手：前搖期間玩家沒有受傷，出手的那一 tick 才受傷。
  - 前搖期間翻滾：出手揮空，玩家沒有受傷。
  - 前搖期間直線後退：被撲擊追上而受傷。
  - 前搖期間轉身衝刺：前搖較長的怪物（例如劫毀獸）揮空。
  - 雙腿壞死時，延後落下的那一擊仍會轉成處決（沿用現有的實戰處決測試）。
  - 每種處決招式各跑一次：站位固定、全程沒有被取消、接觸點造成表列的傷、最後由處決擊殺；途中由另一名「玩家」攻擊怪物可打斷，且傷勢保留。每招拍三到四張關鍵影格截圖，檢查兩個模型沒有互相穿插。
  - 骷髏爆頭：拿弓的骷髏從遠處射中雙腿壞死的玩家，觸發爆頭並擊殺；放箭前打中骷髏可打斷。
  - 死亡畫面：一般死亡與處決死亡各拍一張，確認心臟與赤紅色「處決」。
  - 每個族群各拍獵殺姿態、蓄力、出手三張截圖，整理成對照圖給使用者看。
- 聲音：遊戲的 `SoundManager` 能解析所有事件，所有新 OGG 都能解碼；新事件都有字幕。
- 完整 `build.ps1 build runClientGameTest` 與 CI 通過。

## 撰寫時做的決定（使用者可推翻）

- 受到傷害不會中止前搖。
- 前搖期間怪物會慢慢逼近，撲擊會追擊後退的玩家（上限 1.0 格），讓直線後退躲不掉。
- 狼與北極熊只重做低吼與警告，不動寵物與幼獸的其他聲音。
- 骷髏類、嘎枝、界伏蚌、旋風人、史萊姆類維持合成音色。
- 處決中途的傷：依招式造成骨折或出血，被救下來時保留。
- 受害者自己的攻擊不能打斷處決，只有其他玩家能。
- 處決死亡的心臟用另一顆變化版（撕咬、扯裂的痕跡）。
- 骷髏爆頭的瞄準時間約 1.5 秒，距離以原版弓的射程為限。
